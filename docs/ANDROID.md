# Hunter на Android

Це встановлювана PWA — той самий застосунок і та сама база на ПК. Окремого APK чи публікації в Google Play немає.

## Підключення
1. На ПК відкрий http://127.0.0.1:4318/?phone=1. Натисни «Створити код».
2. Відскануй QR камерою Android, відкрий посилання в Chrome. Код з QR використовується один раз і видаляється з адресного рядка. Можна також відкрити показану HTTPS-адресу й ввести код вручну.
3. Після входу натисни «Встановити Hunter». Якщо кнопки немає: меню Chrome ⋮ → «Додати на головний екран» / «Встановити застосунок». Назва пункту залежить від версії браузера.
4. Відкривай Hunter з іконки на головному екрані. Вибрані проєкти та позначки завдань спільні з ПК.

## Що працює
- Картки, плани участі, збережені матеріали й стан агентів через той самий API.
- Одноразовий код із ПК, 10 хвилин, до 8 невдалих спроб. Телефонна сесія діє до 30 днів і може бути відкликана.
- «Вийти на телефоні» завершує лише поточну сесію. «На телефон» → «Відключити всі телефони» на ПК відкликає всі сесії та поточний код.
- При втраті мережі показується окремий екран. Офлайн-черги дій немає; виконання не підтверджується без відповіді сервера.
- У service worker кешуються лише статичні ресурси та офлайн-сторінка. Картки, API, сесії та коди не кешуються.

## Запуск доступу на ПК
Після дозволу власника запустити Start-Phone.ps1 з папки D:/Projects/ai-hub-hunter-gemini. Скрипт піднімає Hunter, перевіряє SHA256 офіційного Cloudflare-конектора, запускає loopback gateway на 4320 і тимчасовий HTTPS-тунель. Файли й журнали — у data/ на диску D. Автозапуск Windows не налаштовується.

Stop-Phone.ps1 відкликає сесії, вимикає дозволену адресу й зупиняє лише власний перевірений tunnel process. Локальний Hunter продовжує працювати.

## Межі першої версії
ПК, Hunter і тунель мають працювати. Ollama та фонові агенти залишаються на ПК; модель на Android не встановлюється. Трафік HTTPS проходить через Cloudflare. Це не постійне серверне розгортання.

Адреса trycloudflare.com тестова, може змінитися після перезапуску тунелю й не має гарантії доступності. Після зміни адреси потрібно підключитися знову; стару іконку за потреби перевстановити. Для щоденного використання наступний крок — постійна HTTPS-адреса/сервер. Дані залишаються в базі ПК.

Gateway перевіряє точний Host, Origin для змін і захищену HttpOnly/SameSite-сесію; маршрути керування телефонами доступні лише на локальному API. Порт 4318 залишається loopback. Гаманці, підписи й транзакції не виконуються автоматично.

## Перевірки
pytest tests/test_mobile.py: одноразовість/строк коду, обмеження спроб, відкликання, ротація адреси, cookie, Origin/Host, захист керування телефонами від обходу шляхів, помилка backend, зміна спільного проєкту через gateway.

node scripts/phone-browser-smoke.mjs: ізольована SQLite та локальний HTTPS-тест (без тунелю), вхід, спільна картка, ширина 390 px, service worker, офлайн-сторінка, вихід. У локальному self-signed/incognito тесті Chromium блокує саме встановлення; цей тест не підтверджує встановлення на фізичний Android.

Офіційні довідки: https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable і https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/.

## Резервний провайдер
Якщо Cloudflare provisioning API недоступний, після окремого дозволу власника можна запустити Start-Phone.ps1 -Provider localhost-run. Це інший зовнішній провайдер: телефонний HTTP-трафік після TLS-термінації проходить через localhost.run. Захист кодом і cookie залишається в нашому gateway. SSH не використовує особисті ключі або ssh-agent; перший ключ вузла записується в окремий data/phone-known-hosts, наступні підключення перевіряють його. Безкоштовна адреса так само тимчасова. Після отримання URL скрипт перевіряє HTTPS-сторінку входу та відмову API без сесії. Поки ці перевірки не пройшли, успіх не оголошується.

Живу HTTPS-перевірку localhost.run пройдено 10.10.2026 після окремої згоди власника: вхід, API до/після входу, service worker, відсутність помилок встановлюваності Chromium, вихід. Це ще не підтвердження встановлення на фізичний телефон. Адресу дивись у «На телефон» на ПК — вона може змінюватися.

## Без залежності від ПК
Підготовлено [серверний запуск](SERVER.uk.md). Після фактичного перенесення на сервер ПК не потрібен; одноразовий код можна створити через SSH. Поточний тунель залишається прив’язаним до ПК, доки перенесення не завершено.
