# Доступ і метод дослідження — 27.09.2026

## Перевірені маршрути

| Маршрут | Фактичний результат | Для чого використовуємо |
|---|---|---|
| CryptoRank /v3/drophunting/map, наявний ключ | HTTP 200, 1168 назв і slug | Збір каталогу; без оцінки прибутковості за самою назвою |
| /v3/drophunting/1 та /v3/drophunting/1/tasks | HTTP 403 на обох запитах | Не ставити нескінченні повтори; доступ не підтверджений |
| Прямий HTTP сторінки CryptoRank | HTTP 403 | Фіксуємо невдалу перевірку |
| Новий звичайний браузер | Cloudflare, вміст не отримано | Не заявляємо подолання захисту |
| Пошуковий індекс сторінок | Частина карток доступна, може бути застаріла | Часткові дослідницькі нотатки з датою та джерелами |
| Розширення браузера | Реальний MV3 конвеєр пройшов контрольований тест | Імпорт доступних користувачу сторінок; живий доступ не підтверджений |
| Офіційні документи проєкту | Variational: 2 документи, 9782 символи, живий запит успішний | Запасний маршрут щоденного агента для перевірених джерел |

Ключ зберігається лише у локальному .env, який Git ігнорує. Нового платного тарифу не придбано.

## Що переносимо з досвіду відкритих розробок

- [DefiLlama Adapters](https://github.com/DefiLlama/DefiLlama-Adapters): окремі адаптери джерел, прозорі перетворення, можливість перевірити результат. У нас адаптери каталогів і фікстури реального формату карток.
- [Dune Spellbook](https://github.com/duneanalytics/spellbook): відтворювані перетворення onchain-даних. Для дослідження виплат потрібні контракт, події, блоковий діапазон, SQL/код і дата зрізу. З’єднання з Dune ще не реалізоване.
- [Playwright: Chrome extensions](https://playwright.dev/docs/chrome-extensions): перевірка справжнього service worker у persistent Chromium context. Тест розширення вже є; це не підміна live-перевірки зовнішнього сайту.
- [CryptoRank API](https://docs.cryptorank.io/): каталог та завдання є різними endpoint із різним доступом.

Не імпортуємо сторонній код без потреби й не називаємо перегляд README впровадженою інтеграцією.

## Дослідження 1000 проєктів

Період 27.09.2018–27.09.2026. Каталог CryptoRank не є готовою вибіркою mainnet-проєктів. Проєкт, сезон, кампанія та токен — різні сутності; сезони не збільшують кількість унікальних проєктів.

Для кожного кейсу потрібні:
1. Ідентичність проєкту й первинний доказ запуску production/mainnet у періоді.
2. Версії умов: що було відомо до snapshot і що оголосили пізніше.
3. Окремі групи користувачів, мережі, ролі, пороги, дати, винятки.
4. Оголошена алокація, фактичні claims, кількість адрес, одиниці токенів і час зрізу.
5. Витрати: комісії, funding, прослизання, час, ризик капіталу. Невідоме залишається невідомим.
6. Нульові/негативні результати: немає аірдропу, участь була платним продажем, витрати перевищили результат, виключення через умови.

Повний статус обчислюється за доказами, а не береться з відповіді LLM. На цій стадії 11 часткових кейсів, 0 повних. Немає підтвердження, що в заданому періоді знайдеться саме 1000 проєктів, які відповідають усім критеріям; нестачу не заповнюємо вигаданими кейсами.

## Що вже застосовано до агента

- Часові зрізи та походження висновків; стара пошукова копія не переважає прочитану офіційну документацію.
- Приклад Variational: турнір 10–24 вересня завершений; актуальний документ поінтів містить Q4, тоді як пошукова копія містила Q3.
- Частковість звіту видима. Невдале читання агрегатора не називається повним дослідженням.
- Історичні аналогії відокремлені від поточних обов’язкових завдань.
- Ручні позначки виконання зберігаються; новий аналіз не переписує їх.
- Збережена дослідницька нотатка залишається видимою після нового звіту Ollama.
- Пам’ять виправлень подається в наступний аналіз. Навчання ваг моделі не реалізоване.

## Що не вирішено

Багатоджерельна автоматична побудова повного досьє, широке виявлення офіційних сторінок, незалежне onchain-підтвердження виплат, завершення 1000 кейсів та оцінка якості рекомендацій на відкладеній вибірці. Наявність агента й кількість карток не підтверджують якість інвестиційного рішення.
